# Lab 1: Threats vs. Vulnerabilities

As cybersecurity students, we hear "threats" and "vulnerabilities" tossed around together all the time, but keeping their core distinction clear is key to understanding risk. 

Here is a simple breakdown of how they compare and work together:

| Core Aspect | Threat | Vulnerability |
| :--- | :--- | :--- |
| **What is it?** | Potential event, actor, or danger that can cause harm or disrupt an asset. | An internal flaw, weakness, or gap in system design, configuration, or code. |
| **Perspective** | *"What could attack us?"* | *"Where are we exposed?"* |
| **Origin** | Mostly external actors or unpredictable events (hackers, malware, natural disasters). | Internal weaknesses within our setup (unpatched OS, weak passwords, misconfigured firewalls). |
| **Can we control it?** | **No.** You can't directly stop an attacker from trying or prevent malware from existing. | **Yes.** It's entirely on us to patch software, enforce policies, and harden systems. |
| **Real-World Example** | A hacker attempting a brute-force SSH login on a network. | Leaving default root credentials or open, unmonitored ports on a server. |

### The Takeaway
Think of it like this: A **threat** is the danger waiting outside, while a **vulnerability** is an unlocked door. The threat only turns into an actual compromise when a vulnerability is left open to exploit. As security pros, our primary focus is eliminating the vulnerabilities we can control to keep threats harmless.
